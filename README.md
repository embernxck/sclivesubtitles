# SCLiveSubtitles

Синхронные тексты песен для SoundCloud. Бесплатно, без ключей и без аккаунтов.

Вставляешь ссылку на трек — текст едет под музыку. Текста нигде нет? Пишешь его
сам и отбиваешь строки тапами: получается настоящая синхронная разметка, и
остаётся она всем остальным.

Так закрывается дыра, которой лет пятнадцать: сервисы вроде Musixmatch знают
релизы со стримингов, а SoundCloud — это в основном то, что нигде больше не
выходило. Миксы, демо, самиздат. Текстов к такому нет ни у кого, и взяться им
неоткуда, кроме как от слушателей.

---

## Что внутри

- **Текст под музыку** — подсветка по строкам, а если размечено по словам, то и
  по словам, как в караоке. Тап по строке перематывает к ней.
- **Поиск в открытых базах** — сначала своя база, потом
  [LRCLIB](https://lrclib.net). Нашлось готовое — человек ничего не делает.
- **Ввод текста** — простыня как есть, по строке на строку. Пометки вроде
  «[Припев]» убираются сами, пустая строка становится проигрышем.
- **Студия разметки** — включаешь трек и жмёшь кнопку в начале каждой строки.
  <kbd>Пробел</kbd> — тап, <kbd>Backspace</kbd> — шаг назад с перемоткой к
  предыдущей метке. Есть поправка на задержку реакции и режим «по словам».
- **Несколько версий у трека** — перевод, другой залив, чья-то более точная
  разметка. Побеждает не последняя, а лучшая по голосам.
- **Выгрузка `.lrc`** — забрать текст в свой плеер, с пословными метками или без.
- **Отдача в LRCLIB** — разметил у нас, поделился со всеми. По кнопке, только
  своё и только с разрешения владельца копии сервиса.

### Чего он не делает

- **Не трогает звук.** Играет встроенный плеер SoundCloud в iframe: со своей
  рекламой и своим счётчиком прослушиваний. Мы ничего не скачиваем, не
  перекладываем и не проксируем.
- **Не лезет в их API.** Официальное требует `client_id`, а регистрацию
  приложений давно закрыли. Нам хватает открытого oEmbed — он отдаёт название,
  автора, обложку и номер трека без всякого ключа.
- **Не заводит аккаунтов.** Браузер хранит случайный ключ, сервер — только его
  свёртку. Этого хватает, чтобы узнавать «свой» текст и считать голос один раз.
  Ни почты, ни пароля, ни профиля.

## Запуск

Нужен Node 20 или новее. Больше ничего: ни докера, ни отдельной базы, ни
миграций.

```bash
npm install
npm run dev
```

Откроется на `http://localhost:3000`, база ляжет файлом `sclive.db` рядом с
проектом. Схема создаётся сама при первом обращении.

```bash
npm test         # 97 тестов на чистое ядро и базу
npm run typecheck
npm run build
```

### Настройки

Всё необязательное, пример — в `.env.example`.

| Переменная | Зачем |
| --- | --- |
| `DATABASE_URL` | Где база. По умолчанию `file:./sclive.db`. Для облачной — адрес `libsql://…` |
| `DATABASE_AUTH_TOKEN` | Токен облачной базы |
| `SCLIVE_PUBLIC_URL` | Как представляться LRCLIB |
| `SCLIVE_LRCLIB_PUBLISH` | `true` включает кнопку «отдать в LRCLIB». По умолчанию выключено |
| `SCLIVE_REPORT_THRESHOLD` | Сколько жалоб прячет текст до разбора. По умолчанию 3 |

### Где это живёт

Обычный Next.js: разворачивается куда угодно, где он работает. База — libsql,
то есть SQLite: файлом на своей машине, [Turso](https://turso.tech) в облаке.
Бесплатных тарифов и там, и там хватает с запасом — сервис хранит текст, а не
музыку.

## Как устроено

```
браузер                          сервер                    чужие сервисы
────────                         ──────                    ─────────────
iframe SoundCloud  ──позиция──►  /api/track     ──ссылка──► soundcloud.com/oembed
KaraokeView        ◄──текст───   /api/lyrics    ──поиск───► lrclib.net
SyncStudio         ──разметка─►  /api/lyrics/*  ──отдача──► lrclib.net/api/publish
                                      │
                                   libsql
```

Ядро — `src/lib` — написано чистым: ни сети, ни базы, ни React. Поэтому оно всё
под тестами, а не «проверим руками в браузере».

| Файл | Что делает |
| --- | --- |
| `lrc.ts` | Разбор и сборка LRC, включая расширенный с пословными метками |
| `sync.ts` | Движок тап-разметки: тапы, отмена, правка, поправка на задержку |
| `normalize.ts` | Чистка названий SoundCloud и отпечаток трека |
| `soundcloud.ts` | Ссылки и oEmbed |
| `lrclib.ts` | Клиент LRCLIB, включая публикацию |
| `pow.ts` | Доказательство работы, которое LRCLIB просит при публикации |
| `repo.ts` | Запросы к базе |

Несколько решений, которые стоит знать, если будешь править:

- **Позиция досчитывается по часам.** `PLAY_PROGRESS` у SoundCloud приходит
  примерно три раза в секунду — для подсветки по словам этого мало. Между
  событиями позиция считается от последнего известного значения, а
  перерисовка идёт только когда сменились строка или слово.
- **Размеченное руками побеждает размеченное из LRCLIB.** На SoundCloud у трека
  бывает своё вступление или другой монтаж, и чужие метки по нему не лягут.
- **Регистр для поиска приводится в JS.** `lower()` в SQLite умеет только
  латиницу и кириллицу не трогает — поиск по русским названиям без этого не
  работает вовсе.
- **Разметка чужого текста создаёт свою версию,** а не правит чужую: у автора
  текста своя работа, у разметчика — своя.

## Тексты и права

Тексты пишут пользователи. Сервис их не ищет по сайтам, не разбирает чужие
страницы и ничего не импортирует, кроме открытой базы LRCLIB.

На странице трека у каждой версии есть кнопка **«Жалоба»** с отдельным поводом
«нарушает права». Как только жалоб набирается `SCLIVE_REPORT_THRESHOLD` (по
умолчанию три), текст прячется сам, не дожидаясь, пока до него дойдут руки.
Поднимая свою копию, имей в виду: отвечаешь за неё ты, так что оставь способ
с тобой связаться.
